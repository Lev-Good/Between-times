# בין הזמנים — ניהול זמן גישה למחשב (Windows)

תוכנת שולחן עבודה לווינדוס לניהול שעות השימוש במחשב. מגדירים מראש **באילו שעות וימים המחשב מותר** ובאילו **חסום**, והתוכנה אוכפת זאת בפועל — כולל נעילת המסך, מסך חסימה במסך מלא על כל המסכים, ומניעת עקיפה.

נוצר באהבה על ידי **לב טוב דיגיטל** — [digital.levtov.uk](https://digital.levtov.uk/) • [mytovmail@gmail.com](mailto:mytovmail@gmail.com)

## תכונות

- **לוח זמנים שבועי** — לכל יום בשבוע מגדירים חלונות זמן (מותר/חסום), עם שעון 24 שעות שמראה את כל שעות היממה
- **שתי שיטות ברורות** — "המחשב פתוח תמיד (חוץ ממה שחסום)" או "המחשב חסום תמיד (חוץ ממה שמותר)"
- **אכיפה אמיתית** — בשעות החסומות המחשב ננעל (Lock WorkStation) ומופיע מסך חסימה במסך מלא
- **ריבוי מסכים** — חלון חסימה נפרד על כל מסך מחובר
- **מניעת עקיפה** — חסימת Alt+Tab, Win, Ctrl+Esc, Alt+F4 וקיצורים נוספים בזמן חסימה; איבוד מיקוד מחזיר את מסך החסימה
- **שומר-שער (הגנה מפני מנהל המשימות)** — שני תהליכים משגיחים זה על זה: אם הורגים את האפליקציה ממנהל המשימות, שומר-השער מקפיץ אותה מחדש תוך שניות, ולהיפך
- **שעון מהימן** — החסימה נמדדת לפי שעון מונוטוני, כך ששינוי שעון המערכת **לא עוקף** את החסימה
- **זמן התראה לפני הנעילה** — שניות של אזהרה לפני הנעילה (ברירת מחדל: 2 דקות)
- **נעילה ידנית מלאה** — כפתור "נעל עכשיו" מפעיל את מסך החסימה המלא של בין הזמנים (לא רק את נעילת Windows הרגילה), והפתיחה מתבצעת עם סיסמה
- **סיסמה** — כניסה לניהול ההגדרות, שינויים ומסך החסימה — כולם דורשים סיסמה; אימות מתבצע **בתהליך הראשי** (לא בממשק), עם **נעילה זמנית אחרי 5 ניסיונות שגויים** למניעת ניחוש (ברוט-פורס)
- **סיסמה מוצפנת בדיסק** — הסיסמה נשמרת מוצפנת עם DPAPI של Windows (safeStorage) לשחזור למייל בלבד; לא מועברת לממשק ולא נכתבת כטקסט מלא
- **שחזור סיסמה למייל** — כל הבקשות נשלחות לשרת השחזור של בין הזמנים בלבד (Google Apps Script + Google Sheets של המפתח)
- **אופליין מלא** — כל פעולות התוכנה עובדות ללא אינטרנט; רק שחזור הסיסמה ובדיקת עדכונים דורשים רשת
- **עדכונים** — התוכנה בודקת עדכון מרקע ומציגה הודעה בתוך התוכנה + התראת ווינדוס
- **חלונות שחוצים חצות** — למשל 22:00–06:00 (הסוף הוא למחרת בבוקר)
- **מגש מערכת** — רצה ברקע, מצב נוכחי + נעילה מהירה
- **אימות סיסמה כפול** — הקלדה חוזרת בעת הגדרה או החלפת סיסמה
- **הפעלה עם Windows (תמיד פעילה, ללא אפשרות לכיבוי)** — עולה אוטומטית בכל כניסה למחשב, גם עבור **כל המשתמשים** (Registry של המשתמש + של המחשב + משימה מתוזמנת בהרשאות גבוהות); האופציה אינה מוצגת בממשק
- **עדכון חי** — כרטיס מצב עם ספירה לאחור למעבר הבא
- **מצב בהיר/כהה/מערכת** — ערכת נושא הניתנת לבחירה, כולל מעקב אוטומטי אחרי הגדרת Windows בזמן אמת
- **יומן פעילות + דשבורד סטטיסטיקות** — כמה שעות נחסם המחשב היום והשבוע, ניסיונות פתיחה שגויים, מתי נפתח/נחסם
- **חריגים חד-פעמיים** — למשל "להרשות את כל יום שבת" לחופשה/חג, בלי לשנות את הלוח הקבוע (מצוין גם על שעון היום)
- **הודעה אישית במסך החסימה** — מסר מהורה לילד, למשל "נלמד בשקט 🐣"
- **מסך "מצב ההגנה"** — בדיקת תקינות אחת שמראה להורה שכל ההגנות פעילות (הפעלה עם Windows, משימה מתוזמנת, הגדרות משותפות, מנעול Windows, סיסמה, חיבור מייל שחזור)
- **גיבוי ושחזור הגדרות** — הורדת קובץ גיבוי JSON ושחזור מלא, כולל חריגים והודעות — הסיסמה לעולם אינה מועתקת לגיבוי

## העלאת התוכנה לגיטהאב (לשיתוף עם חברים ולבדיקות)

הדרך המומלצת להעלות את **כל** התוכנה לגיטהאב היא באמצעות git מהמחשב (ולא גרירת קבצים בדפדפן — גרירה משמיטה קבצים נסתרים ותיקיות). כך עושים את זה שלב-שלב:

### שלב 1 — יוצרים מאגר ריק בגיטהאב
1. היכנסו ל-[github.com](https://github.com) והתחברו (אם אין חשבון — צרו אחד, חינם).
2. לחצו **New repository** (מאגר חדש).
3. בחרו שם, למשל `ben-hazmanim`.
4. השאירו את האפשרויות **Public/Private** לפי בחירתכם (Private = רק מי שתזמינו יראה; Public = כולם). לחברים לבדיקה — אפשר Private ולהוסיף אותם כ-Collaborators.
5. **אל תסמנו** את התיבות "Add a README", ".gitignore" או "license" — הקבצים האלה כבר קיימים אצלכם בפרויקט ויעלו יחד עם הקוד.
6. לחצו **Create repository**. יופיע דף עם הוראות — שמרו אותו פתוח.

### שלב 2 — מעלים את הקוד מהמחשב
פתחו טרמינל (בווינדוס: הקישו `cmd` בתפריט התחל) ועברו לתיקיית הפרויקט:

```bash
cd "C:\Users\משתמש\Downloads\בין הזמנים"
```

ואז הרצו את הפקודות הבאות (החליפו את `<שם-משתמש>` בשם המשתמש שלכם):

```bash
# 1. אתחול מאגר git מקומי (פעם אחת)
git init

# 2. הוספת כל קבצי הפרויקט (קבצים מוחרגים ב-.gitignore לא יעלו)
git add .

# 3. בדיקה: מה עומד לעלות
git status

# 4. שמירת גרסה ראשונה
git commit -m "גרסה ראשונה — בין הזמנים"

# 5. חשוב: GitHub קורא לענף הראשי "main" (ולא master) — מיישרים את השם
#    לפני הדחיפה, כדי שחברים שיביאו עותק יקבלו את הקוד ולא מאגר ריק!
git branch -M main

# 6. חיבור למאגר בגיטהאב (הכתובת מופיעה בדף שיצרתם בשלב 1)
git remote add origin https://github.com/<שם-משתמש>/ben-hazmanim.git

# 7. העלאה לגיטהאב (בפעם הראשונה משתמשים ב-u)
git push -u origin main
```

אם git מבקש שם משתמש/סיסמה — GitHub כבר לא מקבל סיסמה ישירה, אלא **Token** (ראה להלן).

### הגדרת גישה לגיטהאב מהמחשב (Token)
1. בגיטהאב: לחצו על התמונה שלכם בפינה → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token**.
2. סמנו את ההרשאה `repo` (מספיקה לפעולות קוד) ותוקף ארוך, ולחצו **Generate**.
3. העתיקו את ה-token (מוצג פעם אחת בלבד!).
4. בהעלאה הראשונה, כשתגיעו ללוגין — שם המשתמש שלכם, ובמקום סיסמה הדביקו את ה-token.
5. **מומלץ**: אם התקנתם Git for Windows — Git Credential Manager שומר את ה-token בצורה מאובטחת אוטומטית. לחלופין: `git config --global credential.helper store` (נוח, אבל שומר את ה-token כטקסט פשוט על המחשב — השתמשו רק במחשב אישי).

### שלב 3 — חברים מתקינים ובודקים
כדי שחברים יוכלו **להתקין** את התוכנה בקלות (ולא רק לראות קוד), צריך לפרסם קובץ התקנה:

1. בונים את קובץ ההתקנה (על המחשב שלכם):
   ```bash
   npm install
   npm run dist
   ```
   הקובץ ייווצר בתיקיית `dist/` — למשל `בין הזמנים Setup 1.1.0.exe`.
2. בגיטהאב: דף המאגר → **Releases** → **Create a new release**.
3. ב-**Tag** כתבו את מספר הגרסה, למשל `v1.1.0`. בכותרת: `גרסה 1.1.0`.
4. גררו את קובץ ה-EXE מהתיקייה `dist/` לאזור "Attach binaries" (צירוף קבצים) ולחצו **Publish release**.
5. שלחו לחברים את הקישור: `https://github.com/<שם-משתמש>/ben-hazmanim/releases` — משם הם מורידים את ה-EXE ומתקינים.

### שלב 4 — חברים שבודקים את הקוד עצמו
חברים שמוכנים להריץ מהקוד (מפתחים):

```bash
git clone https://github.com/<שם-משתמש>/ben-hazmanim.git
cd ben-hazmanim
npm install
npm start
```

הם גם יכולים להריץ את הבדיקות: `npm test`.

### עדכונים אחרי שינויים חדשים
בכל פעם שביצעתם שינויים ורוצים שחבר יבדוק:

```bash
git add .
git commit -m "תיאור קצר של מה ששונה"
git push
```

ואם גם פירסמתם גרסה חדשה — עדכנו את הקובץ `version.json` בפרויקט (או פרסמו Release חדש עם ה-EXE) ותוכלו לבדוק את מנגנון העדכונים בתוכנה.

> ⚠️ **חשוב**: אם מילאתם את `SECRET_KEY` האמיתי בסקריפט השחזור (`gas/PasswordRecovery.gs`) או את `RECOVERY_SECRET`/`UPDATE_URL` ב-`main.js` — **אל תעלו את הערכים האמיתיים לגיטהאב ציבורי**. השאירו את הקבועים ריקים/מאובטחים בקוד שב-repo, והציבו את הערכים האמיתיים רק במחשב שלכם או בקובץ מקומי מוחרג (הוספתי `.env` ו-`*.local` ל-.gitignore). הגיליון של Google Sheets שמכיל סיסמאות חייב להישאר פרטי!

## תכונות חדשות: יומן פעילות, חריגים, מצב הגנה וגיבוי

### יומן פעילות וסטטיסטיקות (הלשונית "סטטיסטיקות")
- שעות חסימה **היום והשבוע**, כמות הפעלות ונעילות, וניסיונות פתיחה שגויים (כולל נעילות זמניות).
- רשימת אירועים אחרונים (פתיחה/חסימה/ניסיון שגוי) עם תאריך ושעה.
- היומן נשמר בקובץ `activity.log` בתיקיית הנתונים (עד 1000 אירועים אחרונים, כדי לא לתפוח).

### חריגים חד-פעמיים (הגדרות → חריגים)
- מאפשרים לעקוף את הלוח הקבוע ליום מסוים בלבד — למשל "אפשר את כל יום שישי".
- כל חריג הוא רשומה עם תאריך וסוג (מותר/חסום), וניתן למחוק אותו בקלות.
- החריג מוצג כפס על שעון היום המתאים בלוח השבוע.
- לחריג שחסום — סיסמת מנהל אינה פותחת אותו; הפתיחה מתבצעת רק מהממשק (בדומה למנעול הידני).

### הודעה אישית במסך החסימה (הגדרות → מסך חסימה)
- הודעה קצרה (עד 120 תווים) שתופיע במסך החסימה מעל שדה הסיסמה, למשל "נלמד בשקט".
- מוצגת גם במנעול ידני ובחסימה רגילה — בכל מסך.

### מצב ההגנה (הגדרות → בדיקת תקינות)
- בדיקה אחת שמראה מצב ירוק/אדום לכל הגנה:
  - הפעלה עם Windows (עבור המשתמש והמחשב), משימה מתוזמנת בהרשאות גבוהות, הגדרות משותפות, נעילת Windows, סיסמה מוגדרת ומייל שחזור מחובר.
- בכל בדיקה יש כפתור תיקון לפעולות שאפשר לתקן אוטומטית.

### גיבוי ושחזור (הגדרות → גיבוי)
- **ייצוא**: קובץ JSON עם כל ההגדרות (לוח, שיטה, חריגים, הודעות, ערכת נושא). **הסיסמה אינה נכללת** — גם הגיבוי לא חושף אותה.
- **ייבוא**: בחירת קובץ גיבוי ובדיקת תקינות אוטומטית — קובץ לא תקין או קטן מדי נדחה.
- הגיבוי שומר על סיסמת התוכנה הנוכחית (אין איפוס סיסמה דרך ייבוא).

## הגדרת עדכונים דרך GitHub

הדרך המומלצת: **לא מעלים את כל התוכנה לגיטהאב כדי לבדוק עדכונים** — אלא משתמשים בגיטהאב רק כתחנת הורדה ומודיעים על גרסה חדשה דרך קובץ JSON קטן. כך זה עובד:

1. **מפרסמים את קובץ ההתקנה** — בכל גרסה חדשה יוצרים ב-GitHub *Release* ומצרפים אליו את קובץ ה-EXE (או מעלים את הקובץ לכל מקום אחר, למשל Google Drive).
2. **מעלים את `version.json`** (קיים בתיקיית הפרויקט) למקום נגיש באינטרנט. הפורמט:
   ```json
   { "version": "1.2.0", "url": "https://github.com/your-user/ben-hazmanim/releases/latest", "notes": "מה חדש" }
   ```
   אפשר להעלות את הקובץ ל-GitHub Pages של ה-repo (כתובת דוגמה: `https://<משתמש>.github.io/<repo>/version.json`) או להשתמש ב-link ישיר של raw (כתובת דוגמה: `https://raw.githubusercontent.com/<משתמש>/<repo>/main/version.json`).
3. **מגדירים את הכתובת בקוד (למפתח בלבד)** — הקבוע `UPDATE_URL` ב-`main.js`. אין שדה בממשק: משתמשים רגילים לא רואים ולא משנים את מקור העדכונים.
4. בכל גרסה חדשה — מעדכנים את `version` ואת קישור ההורדה בקובץ `version.json`, והתוכנה תודיע למשתמשים על העדכון (באנר בתוכנה + התראת ווינדוס).

התוכנה משווה את הגרסה מרקע עם ההפעלה, ומציגה הודעה כשקיים עדכון. ניתן לבדוק ידנית עם "בדוק עדכונים".

> הערה: עדכון אוטומטי מלא (התקנה שקטה של גרסה חדשה ללא צעד ידני) דורש שילוב של `electron-updater` — אפשר להוסיף בהמשך.

## שחזור סיסמה למייל (שרת השחזור של בין הזמנים)

כל בקשת שחזור סיסמה נשלחת **תמיד** לשרת השחזור של בין הזמנים בלבד (אפליקציית Google Apps Script המחוברת לגיליון Google Sheets של המפתח), שם נשמרות כל הסיסמאות. כתובת השרת קבועה בתוכנה (`RECOVERY_URL` ב-`main.js`) ואינה ניתנת לשינוי.

### מה להגדיר בתוכנה (הגדרות → אבטחה ושחזור סיסמה)

1. **כתובת מייל לשחזור** — המייל אליו תישלח הסיסמה כששוכחים אותה.

המפתח הסודי (`RECOVERY_SECRET` ב-`main.js`) מוגדר על ידי המפתח בלבד ואינו מופיע בממשק המשתמש. מקור העדכונים (`UPDATE_URL` ב-`main.js`) גם הוא מוגדר רק בקוד.

בעת לחיצה על "שכחתי סיסמה" (במסך הכניסה או במסך החסימה) — הבקשה נשלחת לשרת, הסיסמה נשלחת למייל המוגדר, והבקשה נרשמת בגיליון של המפתח. יש גם כפתור "שליחת סיסמה לבדיקה" בהגדרות כדי לוודא שהכול מחובר.

### פריסת הסקריפט (למפתח בלבד)

1. פתחו גיליון Google Sheets חדש.
2. תפריט: **Extensions → Apps Script** (הרחבות → אפליקציות סקריפט).
3. הדביקו את תוכן הקובץ [`gas/PasswordRecovery.gs`](gas/PasswordRecovery.gs) והחליפו את `SECRET_KEY` בערך אקראי ארוך.
4. **Deploy → New deployment → Web app**: הרשאות "Anyone" (כל אחד), Execute as: Me.
5. עדכנו את הקבוע `RECOVERY_URL` ב-`main.js` לכתובת שנוצרה, ואת הקבוע `RECOVERY_SECRET` לאותו סוד שהגדרתם בסקריפט.
6. שמרו את הגיליון **פרטי** — הוא מכיל סיסמאות.

> אם שליחת המייל "לא עבדה" — כמעט תמיד הסיבה היא שהמפתח הסודי בתוכנה אינו תואם ל-`SECRET_KEY` בסקריפט, או שהסקריפט עדיין לא פורסם (Deploy). השתמשו בכפתור "שליחת סיסמה לבדיקה" כדי לאמת.

## הפעלה עם Windows — עלייה ראשונה וחסימת כל המשתמשים

- התוכנה נרשמת ב-**שלושה מקומות** כדי לעלות מוקדם בכניסה ולכסות את כל המשתמשים:
  1. מפתח ה-Run של המשתמש הנוכחי (`HKCU`).
  2. מפתח ה-Run של המחשב (`HKLM`) — כך שגם **חשבון חדש** שייפתח במחשב יריץ את התוכנה בכניסה.
  3. **משימה מתוזמנת בעת כניסה עם הרשאות גבוהות** (HIGHEST) — כך שהתוכנה עולה מוקדם, לפני רוב התוכנות האחרות, ומשתמשת בהגדרות המשותפות.
- **הגדרות משותפות לכל המשתמשים**: כשהתוכנה רצה עם הרשאות מנהל, ההגדרות נשמרות ב-`%ProgramData%\BenHazmanim\settings.json` — כך שכל חשבון במחשב נחסם לפי אותו לוח זמנים (יש הגירה אוטומטית מקובץ המשתמש הישן).
- **חסימת יצירת חשבונות חדשים**: כשהתוכנה רצה עם הרשאות מנהל היא מסתירה את דף "חשבונות" בהגדרות Windows (מדיניות `SettingsPageVisibility`), שהיא הדרך הרגילה להוסיף משתמש/חשבון חדש.
- מגבלה ידועה: יצירת חשבון באמצעות פקודת מנהל (`net user` וכדומה) או דרך ניהול מחשבים דורשת הרשאות מנהל בכל מקרה — חשבון רגיל לא יכול ליצור חשבונות בלי סיסמת מנהל.
- הערה: מדיניות ההסתרה (`SettingsPageVisibility`) נכתבת ל-HKLM ונשארת גם אחרי הסרת התוכנה. כדי לבטלה ידנית — מחקו את הערך `SettingsPageVisibility` מ-`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\Explorer`.

## איך זה עובד

1. **לוח הזמנים** נשמר כקובץ `settings.json` (למשתמש או משותף — ראו לעיל).
2. תהליך רקע בודק את הזמן **כל 5 שניות**, לפי **שעון מונוטוני** שאינו מושפע משינוי שעת המערכת.
3. כשמגיעים לשעת חסימה: מסך חסימה במסך מלא **על כל מסך מחובר** (ללא כפתורי סגירה), קיצורי מערכת נחסמים, ואחרי זמן ההתראה (ברירת מחדל: 2 דקות) ננעל מסך Windows.
4. סיסמה שנזנה במסך החסימה נבדקת **בתהליך הראשי** (לא בממשק), ונעולה זמנית ל-60 שניות אחרי 5 ניסיונות שגויים. הצלחה פותחת את המחשב **עד המעבר הבא בלוח הזמנים** (ואז ננעל שוב).
5. גם אם סוגרים את חלון ההגדרות — התוכנה נשארת פעילה במגש ואוכפת את הלוח.
6. **שומר-שער**: האפליקציה מפעילה תהליך שמירה נפרד שמנטר אותה. אם התהליך הראשי נסגר ממנהל המשימות — השומר מקפיץ אותו מחדש תוך שניות (לפי קבצי heartbeat בתיקיית הנתונים). גם אם הורגים את השומר — התהליך הראשי מקפיץ אותו מחדש. **לסגירה מלאה** יש להשתמש ב"יציאה" מתפריט המגש.

> הערה: אם שכחתם את הסיסמה ואין מייל מוגדר — מחקו את הקובץ `settings.json` מהתיקייה
> `%APPDATA%\ben-hazmanim` (או מהתיקייה `%ProgramData%\BenHazmanim` אם הרצתם כמנהל), או התקינו מחדש. שימו לב שמחיקת הקובץ מאפסת גם את לוח הזמנים.

## מבנה הקבצים

```
main.js                    — תהליך ראשי: אכיפה, שעון מהימן, חסימת קיצורים, שחזור, עדכונים
preload.js                 — גשר מאובטח בין הממשק לתהליך הראשי
scheduler.js               — מנוע חישוב לוח הזמנים (משותף)
renderer/index.html        — ממשק ההגדרות (עברית, RTL, מסך כניסה)
renderer/block.html        — מסך החסימה (כל המסכים)
renderer/styles.css        — עיצוב
renderer/app.js            — לוגיקת הממשק
gas/PasswordRecovery.gs    — סקריפט שחזור הסיסמה (Google Apps Script)
test/scheduler.test.js     — בדיקות יחידה
scripts/generate-icon.js   — מחולל אייקונים (ללא תלות חיצונית)
scripts/build-preview.js   — בונה preview.html עצמאי לתצוגה בדפדפן
version.json               — מקור עדכונים לדוגמה (לפרסום ב-GitHub)
```

## תצוגת ממשק בדפדפן (ללא הרצת Electron)

```bash
npm run preview
```

מייצר קובץ `preview.html` עצמאי שאפשר לפתוח בדפדפן. ההגדרות נשמרות ב-localStorage.
