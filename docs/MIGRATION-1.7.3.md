# Migration and Release Gate: 1.7.2 → 1.7.3

## Schema Migration

**אין מיגרציה.** `schemaVersion` נשאר `2`, אין שדות חדשים ואין שינוי במבנה
הנתונים. הלוח השבועי, החריגים, הסיסמה, שחזור הסיסמה, שותף האחריות, התוכנות
המאושרות, האתרים, מכסת הזמן היומית (`usage.json`), סייר הקבצים, הפרופילים,
ערכת הנושא והרישיון — כולם נשמרים כמו שהם.

זו עליית **פאץ'** לתיקון תקלה בלבד.

## למה הגרסה הזו קיימת — 1.7.2 פגומה

קובץ ההתקנה של 1.7.2 **אינו שמיש באף מחשב**, ולא ניתן לתקן אותו בדיעבד:

- מניפסט ההרשאה שלו תוקן **בתוך ה-EXE, אחרי הבנייה** (שינוי של 20 בתים באותו
  אורך). ההנחה הייתה ששינוי באורך זהה אינו נוגע במבנה הקובץ.
- ההנחה הייתה שגויה: ל-NSIS יש **בדיקת שלמות פנימית של המתקין**, והיא מתבצעת
  בזמן ההרצה. כל שינוי בית בקובץ — בכל מקום — מפיל את המתקין.
- התוצאה בפועל: המתקין יוצא מיד בקוד 2, **בלי חלון, בלי הודעת שגיאה ובלי
  להתקין דבר** (אומת במבחן מבוקר: קובץ מקורי → קוד 0; קובץ עם בית שונה ב-stub,
  במניפסט, באמצע ובסוף → קוד 2 בארבעתם; בהרצה רגילה אין כל חלון).
- כלומר 1.7.2 לא הותקנה אצל אף אחד — לא מתוך התוכנה, ואף לא בהתקנה ידנית.
  אצל מי שהעדכון כבר הורד, ההתנהגות שנראתה למשתמש הייתה: התוכנה נסגרה ("מתקין")
  ולא חזרה, בלי חלון UAC — בדיוק מה שתוקן.

מכאן שגם **הנכס שפורסם** (`Setup.1.7.2.exe`, טביעה `8d6e818b…`, 92,111,797
בתים) פגום, ואין דרך "לתקן" אותו: כל נגיעה נוספת בו רק מחמירה.

## מה השתנה (טכנית)

1. **המניפסט נקבע בזמן הקומפילציה.** `scripts/patch-nsis-template.js` מחליף שורה
   אחת בקובץ המקור של תבנית electron-builder
   (`templates/nsis/installer.nsi`: `RequestExecutionLevel admin` → `user`) —
   **לפני** makensis מריץ. התוצאה זהה למה ש-1.7.2 ניסתה להשיג, אך בלי לגעת
   בקובץ שנבנה: המתקין מופץ עם `asInvoker`.
2. **ההחלה אוטומטית ואכופה.** היא רצה ב-`postinstall` (כדי ש-`npm ci` לא יחזיר
   את המצב השבור) וגם בראש `npm run dist`. אם השורה לא נמצאה בתבנית — הסקריפט
   נכשל בקול והבנייה נעצרת (לא נבנה מתקין שדורש הרשאות בשקט).
3. **`scripts/patch-installer-manifest.js` הוסר** (המנגנון שהרג את המתקין), יחד
   עם המסלול של `nsis.script` (עותק של התבנית — מבטל את בניית המסיר ומפיל את
   הבנייה) ו-`!define admin user` (אינו עובד: מעבד המקדים של NSIS מחליף סמל רק
   בראש שורה, לא כארגומנט של פקודה).
4. **אימות לפני ואחרי הבנייה** (`scripts/verify-installer-manifest.js`):
   לפני — שההחלה בתוקף, שאין `nsis.script`, שההתקנה נשארת `perMachine`, ושאין
   סקריפט שתיקן EXE בדיעבד; אחרי — שהמתקין הוא `asInvoker`, שאין בו
   `requireAdministrator`, ושהוא זהה לטביעת הבנייה (`latest.yml`). כלומר: קובץ
   שנערך אחרי הבנייה — נדחה, בדיוק כמו התקלה של 1.7.2.
5. **המתקין מרים את עצמו** ב-`preInit` (`build/installer.nsh`) — ללא שינוי
   מ-1.7.2: `ExecShell "runas"` על עצמו עם כל הארגומנטים (`/S`), לפני כתיבת
   `quit.flag`, ובכשל — הודעה בעברית והמתקין יוצא בלי לגעת בתוכנה.

## שינויי התנהגות שההורה צריך להכיר

1. **בזמן עדכון מתוך התוכנה מופיע חלון אישור של Windows (UAC).** בחשבון ילדים
   (שאינו מנהל) יש לאשר — או להזין סיסמת מנהל. זה המצב המתוכנן מ-1.7.2.
2. **ביטול חלון האישור אינו סוגר את התוכנה** (בגרסה 1.7.1 ומעלה). בגרסאות
   ותיקות (עד 1.7.0) התוכנה נסגרת מיד עם הפעלת המתקין, לפני שהחלון מופיע —
   זה טיב הקוד הישן, ואין לגרסה החדשה דרך לשנות אותו.
3. **מי שעל 1.7.2** — כלום לא נשבר בדיעבד, פשוט ההתקנה מעולם לא בוצעה. הם
   מתקינים את 1.7.3 בהתקנה ידנית (או ממתינים — ראו הנתיבים למטה).
4. **הסרה** מתוך התוכנה ממשיכה לעבוד כפי שתוקנה ב-1.7.1.

## שלבי השחרור (1.7.3 ואילך)

1. עדכון הגרסה ב-`package.json` וב-`renderer/index.html`.
2. `npm test` — כל הבדיקות.
3. **`npm run dist`** — החלה → אימות מקדים → בנייה → אימות. הפלט הרצוי:
   ```
   patch-nsis-template: …installer.nsi — הוחל כעת (RequestExecutionLevel user)
   verify-installer-manifest (pre): המנגנון תקף
   …
   verify-installer-manifest: …\dist\Setup.<version>.exe
     מניפסט: asInvoker (נקבע בזמן הקומפילציה) — ללא requireAdministrator
     שלמות מול מטא-דאטה של הבנייה: ok
   ```
   > ⚠️ אין לבנות עם `electron-builder` ישירות בלי ההחלה: מתקין כזה יישאר עם
   > `requireAdministrator`. `postinstall` דואג לכך שההחלה תהיה בתוקף בכל
   > התקנה מחדש של החבילות, וקיימת בדיקה אוטומטית שנכשלת על ארטיפקט כזה.
4. אימות ידני קצר של המניפסט (רשות — האימות האוטומטי כבר עשה זאת):
   ```powershell
   $b=[IO.File]::ReadAllBytes("dist\Setup.1.7.3.exe"); $s=[Text.Encoding]::UTF8.GetString($b)
   if ($s -match 'requireAdministrator') { "NOT PATCHED" } else { "asInvoker — תקין" }
   ```
5. חישוב ה-SHA-256 מהקובץ **הסופי** ועדכון `version.json`.
6. Commit → דחיפת **התג בלבד** → יצירת ה-Release עם ה-EXE → **ורק אז** דחיפת
   `main` (כך ש-`version.json` החי — שנקרא מ-`raw.githubusercontent.com` —
   מתעדכן רק כשהמהדורה כבר קיימת).
7. **ניקוי 1.7.2:** המהדורה של 1.7.2 מכילה נכס שאינו שמיש. יש לסמן אותה
   בהודעה ברורה (או למחוק את הנכס) כדי שאיש לא יוריד אותה שוב. אין לערוך את
   הקובץ ולא להעלות אותו מחדש.
   > **בוצע (23/9/2026):** הנכס `Setup.1.7.2.exe` הוסר מהמהדורה, ונוסח המהדורה
   > נפתח באזהרה ברורה (הנוסח המקורי נשמר למטה כתיעוד היסטורי). התג `v1.7.2`
   > נשאר, כך שהמקור ניתן לשחזור.

## מגבלות

- הרצת המתקין **לא בוצעה** בסביבת העבודה שבה נבנתה הגרסה: המחשב הזה מריץ את
  ההתקנה הפעילה (1.6.5), והרצת מתקין הייתה משנה אותה. מה שאומת: המניפסט בקובץ
  שנבנה, ההחלה על התבנית, שהבנייה מייצרת מסיר תקין (חתום ומוטמע), הידור סקריפט
  ה-NSIS, וסדר הפעולות ב-`preInit` מול ההגנות שבדיקות אוטומטיות מאמתות.
- מה שאומת **לגבי 1.7.2** הוא חד-משמעי: שינוי בית בקובץ מפיל מתקין NSIS, וקובץ
  1.7.2 שפורסם מכיל שינוי כזה — כלומר הוא אינו שמיש.
