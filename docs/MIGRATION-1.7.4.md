# מיגרציה 1.7.3 → 1.7.4 — עדכון שלא הותקן כבר לא נכשל בשקט

תאריך: 2026-09-23
סוג: פאץ' — **אין מיגרציית נתונים**. הגדרות, זמנים וסיסמאות נשמרים כפי שהם.

---

## מה בדיוק היה שבור

התלונה: "התוכנה מורידה את הגרסה המעודכנת וסוגרת את עצמה, אבל הגרסה המעודכנת לא
מותקנת."

השרשרת שאומתה במחשב אמת:

1. התוכנה מורידה את המתקין, כותבת דגלי עצירה, מפעילה אותו ב-`spawn` (CreateProcess)
   ונסגרת.
2. המתקין (1.7.3 ומעלה) מופץ עם מניפסט `asInvoker` ומרים את עצמו ב-`preInit`
   (`ExecShell "runas"`), ואז מחכה שהתוכנה תצא.
3. **אם התוכנה (או שומר-השער שלה, או המשתמש שלחץ על הסמל, או השומר המערכתי)
   עלתה מחדש בזמן החלפת הקבצים** — קובץ ההרצה פתוח ו-`resources/app.asar` ממופה,
   ושניהם אינם ניתנים להחלפה.
4. ל-electron-builder יש לכך מסלול נסיגה שקט: אחרי 5 נסיונות העתקה של שנייה
   (`CopyFiles` + `IfErrors`) הוא **מוחק את `$PLUGINSDIR\7z-out`** ומחלץ ישירות
   ל-`$INSTDIR` עם `Nsis7z::Extract`, **שמתעלם משגיאות**. התוצאה: חלק מהקבצים
   הוחלפו, חלק לא, **וקוד היציאה הוא 0**.
5. במסלול השקט (`/S`) גם `MessageBox ... /SD IDRETRY` שהמתקין מציג אינו נראה
   למשתמש. כלומר: התוכנה סגורה, הגרסה לא השתנתה, ואף אחד לא יודע.

הנוסף: במחשב שבו מאגר WBEM פגום (נפוץ אחרי שדרוגי Windows) נכשלים `tasklist`
ו-`Get-CimInstance` (\"Invalid class\") — והבדיקה המובנית של electron-builder
מבוססת בדיוק עליהם. המתקין "לא רואה" את התוכנה שרצה, וממשיך להעתיק לתוך קבצים
נעולים. זו הסיבה שרבות מההגנות כאן אינן תלויות ב-WMI.

## מה נעשה בגרסה הזו

| הגנה | מה היא מונעת |
| --- | --- |
| עצירה ב-`Get-Process` (בלי WMI), לפי נתיב ההתקנה **וגם** העותק המוגן, בלולאה של עד 15 שניות | המתקין "לא רואה" תוכנה שרצה, או שהשומר מקפיץ אותה חזרה בזמן ההחלפה |
| סימן `update-in-progress.json` (עם pid) שהמתקין כותב מתחילתו ועד סופו, והתוכנה יוצאת כשהיא רואה אותו | התוכנה עולה מחדש באמצע ההחלפה ונועלת את הקבצים |
| אימות בסוף ההתקנה (`$PLUGINSDIR\7z-out` חסר = ההעתקה האטומית נכשלה) | "הצלחה" שהיא בעצם התקנה חלקית |
| תיקון עצמי: עצירה חוזרת, חילוץ מחדש מ-`app-64.7z` שבתוך המתקין, העתקה חוזרת, אימות גודל `app.asar` | התקנה חלקית שנשארת חלקית לתמיד |
| הודעה בעברית + `update-result.json` בכשל | כשל שקט (ההודעה מוצגת גם בהתקנה שקטה — בלי `/SD`, בכוונה) |
| התוכנה מדווחת בהפעלה הבאה: מדוח המתקין, ומסימן "עדכון ממתין" | המקרה שהמתקין לא רץ בכלל, או נתקע |
| יומן `%TEMP%\BenHazmanim-Update.log` — כל שלב עם pid | חוסר היכולת לאבחן כשל מהמחשב של המשתמש |

### רשומות השלבים ביומן ההתקנה

```text
[preinit-start] pid=7000 …            ← התהליך שהופעל (לא מוגבר)
[preinit-elevate-dispatched] pid=7000 ← הרים את עצמו ויצא; התהליך המורם ממשיך
[preinit-start] pid=6656 …            ← התהליך המורם
[preinit-proceed-elevated] pid=6656   ← יש הרשאות, ממשיכים
[preinit-app-wait-done] pid=6656      ← התוכנה יצאה (או חוסלה)
[app-check-running] pid=6656          ← בדיקת "התוכנה רצה" (לא תלויה ב-WMI)
[install-section] pid=6656            ← החלפת הקבצים החלה
[verify-atomic-ok] pid=6656           ← ההעתקה האטומית הצליחה — ההתקנה הושלמה
```

במסלול כשל תופיע במקום האחרון שורה אחת מ-`verify-needs-repair` /
`verify-repaired-ok` / `verify-FAIL`, ובהתאם לכך יהיה `update-result.json`.

### דוחות וקבצים שהמתקין והתוכנה מחליפים ביניהם

| קובץ (ב-`%ProgramData%\BenHazmanim`) | מי כותב | מתי | מי קורא |
| --- | --- | --- | --- |
| `update-in-progress.json` | המתקין (`preInit`) | מתחילת ההתקנה | התוכנה, באתחול — יוצאת מיד אם ה-pid חי |
| `update-result.json` | המתקין (`customInstall`) | בסוף ההתקנה | התוכנה, באתחול — מדווחת אם `ok:false` והגרסה לא השתנתה |
| `update-pending.json` | התוכנה | לפני שהיא נסגרת, אחרי שהמתקין אומת רץ | התוכנה, באתחול — מדווחת אם הגרסה לא השתנתה |

## מה המשתמש צריך לעשות

**כלום מיוחד.** עדכון מתוך התוכנה (הגדרות → עדכון) אמור לעבוד כעת, וגם התקנה
ידנית של הקובץ מעמוד ההורדות. אם בזמן ההתקנה מופיע חלון אישור של Windows (UAC)
— יש לאשר אותו.

אם בעבר לחצתם על "עדכן" והתוכנה נסגרה בלי שהגרסה התעדכנה, הגרסה הזו היא התיקון.

> **אם העדכון לא עבד גם כעת** — יש עכשיו מה לשלוח: הקובץ
> `%TEMP%\BenHazmanim-Update.log` (אפשר לפתוח אותו בהרצה: `notepad
> "%TEMP%\BenHazmanim-Update.log"`), וקובץ `%ProgramData%\BenHazmanim\update-result.json`
> אם הוא קיים. השלב האחרון שנרשם ביומן מצביע בדיוק על מה שנכשל.

## אימות שנעשה בפועל (2026-09-23)

- **קצה-לקצה** על מחשב אמת, בהפעלה זהה לזו של התוכנה (`spawn` detached עם `/S`):
  התהליך הלא-מורם יצא בקוד 2 (ההרמה בוצעה), התהליך המורם רץ (pid 6656),
  `update-in-progress.json` = `{"pid":6656,"version":"1.7.4"}`, תהליכי התוכנה
  חוסלו, `resources/app.asar` הוחלף בפועל (891,408 → 893,481 בתים),
  `update-result.json` = `{"ok":true,"stage":"atomic"}`, והתוכנה עלתה מחדש.
- **מסלול "העדכון לא רץ"**: הונח `update-pending.json` לגרסה 9.9.9, התוכנה
  הופעלה מחדש — נרשם `{"type":"update-failed","details":{"version":"9.9.9","stage":"no-install"}}`
  והסימן נמחק.
- **הבנייה**: `npm run dist` → 0, `dist/Setup.1.7.4.exe` = 92,112,886 בתים,
  מניפסט `asInvoker`, שלמות מול מטא-דאטה של הבנייה — ok, טביעה `31b56f86…`.
- **בדיקות**: `npm test` — 350 בדיקות, 0 כשלים, 2 מדולגות.

## מה שאינו בגרסה הזו

- אין חתימת Authenticode (ההפצה עצמאית; ההגנה היא מקור GitHub + HTTPS +
  SHA-256 מ-`version.json`). לכן Windows SmartScreen עשוי להציג אזהרה בהתקנה
  ידנית — "מידע נוסף" → "הפעל בכל זאת".
- אין שדרוג מדורג של סכימת ההגדרות בגרסה זו (לא השתנתה).
