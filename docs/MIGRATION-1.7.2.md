# Migration and Release Gate: 1.7.1 → 1.7.2

## Schema Migration

**אין מיגרציה.** `schemaVersion` נשאר `2`, אין שדות חדשים ואין שינוי במבנה
הנתונים. הלוח השבועי, החריגים, הסיסמה, שחזור הסיסמה, שותף האחריות, התוכנות
המאושרות, האתרים, מכסת הזמן היומית (`usage.json`), סייר הקבצים, הפרופילים,
ערכת הנושא והרישיון — כולם נשמרים כמו שהם.

זו עליית **פאץ'** לתיקון תקלה בלבד.

## מה השתנה (טכנית)

1. **קובץ ההתקנה מופץ עם מניפסט `asInvoker`** במקום `requireAdministrator`.
   הסיבה: הפעלה של קובץ שדורש הרשאות מנהל מתהליך שאינו מוגבר נכשלת **מיד**
   (שגיאה 740) — בלי חלון UAC ובלי שגיאה. זו הסיבה שהעדכון מתוך התוכנה "התקין"
   ולא התקין כלום (גרסאות עד 1.7.1). התיקון נעשה אחרי הבנייה על ידי
   `scripts/patch-installer-manifest.js` (חלק מ-`npm run dist`) — שינוי של 20
   בתים באורך זהה, בלי שינוי מבנה ה-EXE.
2. **המתקין מרים את עצמו.** ב-`preInit` (לפני שהוא נוגע בתוכנה) הוא מפעיל את
   עצמו מחדש בפעולת `runas` (ShellExecuteEx — זה מה שמציג את חלון ה-UAC) ומעביר
   הלאה את כל הארגומנטים, כולל `/S` של התקנת עדכון שקטה. התהליך המקורי יוצא,
   והמורם ממשיך את ההתקנה במקומו.
3. **ההגנה כפולה:** התוכנה (מ-1.7.1) מרימה את המתקין דרך `elevate.exe`, וגם
   המתקין מרים את עצמו. כל אחד מהם לבדו מספיק.

## שינויי התנהגות שההורה צריך להכיר

1. **בזמן עדכון מתוך התוכנה מופיע חלון אישור של Windows (UAC).** בחשבון ילדים
   (שאינו מנהל) יש לאשר את הבקשה — או להזין סיסמת מנהל. קודם לכן ההתקנה פשוט
   לא בוצעה, בשקט.
2. **ביטול חלון האישור אינו סוגר את התוכנה.** ההרמה מתבצעת **לפני** כתיבת
   `quit.flag` (הדגל שסוגר את התוכנה), ואם האישור לא ניתן — מוצגת הודעה ברורה
   והתוכנה ממשיכה לעבוד. שימו לב: בגרסאות **ותיקות** (עד 1.7.1) התוכנה נסגרת
   מיד עם הפעלת המתקין, לפני שחלון ה-UAC מופיע — זה טיב הקוד הישן, ואין לגרסה
   החדשה דרך לשנות אותו.
3. **בחשבון עם הרשאות מנהל** ההתקנה נשארת שקטה כשהיא מופעלת מוגברת (התוכנה
   מרימה אותה), אך הפעלה ידנית של קובץ ההתקנה תמיד תציג חלון אישור — כמו קודם.
4. **הסרה** מתוך התוכנה ממשיכה לעבוד כפי שתוקנה ב-1.7.1.

## ✅ אין צורך בהתקנה ידנית — זו כל מטרת הגרסה

בניגוד ל-1.7.1 (שדרשה התקנה ידנית חד-פעמית, כי התיקון היה **בתוך** התוכנה),
כאן התיקון יושב ב**קובץ ההתקנה שמופץ** — כלומר בדיוק בדבר שגרסאות מותקנות
מורידות. לכן:

- גרסה מותקנת **1.6.5 / 1.7.0 / 1.7.1** → לוחצים "עדכן", מאשרים את חלון
  ה-UAC, וההתקנה מתבצעת ומפעילה את התוכנה מחדש.
- הדבר היחיד שהמשתמש חייב לעשות: **לאשר את חלון ההרשאות של Windows**.

## שלבי השחרור (1.7.2 ואילך)

1. עדכון הגרסה ב-`package.json` וב-`renderer/index.html`.
2. `npm test` — כל הבדיקות.
3. **`npm run dist`** — הבנייה **וגם** תיקון המניפסט. הפלט כולל:
   ```
   patch-installer-manifest: עודכן …\dist\Setup.<version>.exe
     מניפסט: level="requireAdministrator" → level="asInvoker"
     גודל: … בתים (ללא שינוי)
   ```
   > ⚠️ אין לבנות עם `electron-builder` ישירות: מתקין כזה יישאר עם
   > `requireAdministrator`, ועדכון מתוך התוכנה ייכשל שוב בשקט בגרסאות ותיקות.
   > קיימת בדיקה אוטומטית שנכשלת על ארטיפקט כזה.
4. אימות ידני של המניפסט (חובה, חד-פעמי ומהיר):
   ```powershell
   $b=[IO.File]::ReadAllBytes("dist\Setup.1.7.2.exe")
   $s=[Text.Encoding]::UTF8.GetString($b)
   if ($s -match 'requireAdministrator') { "NOT PATCHED" } else { "asInvoker — תקין" }
   ```
5. חישוב ה-SHA-256 מהקובץ **הסופי** (אחרי התיקון) ועדכון `version.json`.
6. Commit → דחיפת **התג בלבד** → יצירת ה-Release עם ה-EXE → **ורק אז** דחיפת
   `main` (כך שהעדכון נפתח למשתמשים רק כשהמהדורה קיימת).

## נוסח מוצע ל-`notes` (ב-`version.json`)

> גרסה 1.7.2 — עדכון מתוך התוכנה עובד כעת גם בלי הרשאות מנהל. מעתה קובץ ההתקנה
> מציג חלון אישור של Windows (UAC) ומרים את עצמו להרשאות; גם גרסאות ותיקות
> (1.6.5 ומטה) מתעדכנות כעת מתוך התוכנה — אין צורך בהתקנה ידנית. יש לאשר את
> חלון ההרשאות בזמן העדכון.

## מגבלות

- הרמת ההרשאות וההתקנה **לא נבדקו בהתקנה אמיתית** בסביבת העבודה שבה בוצעה
  הגרסה (אין VM, והרצת מתקין הייתה משנה את המחשב שבו פותחה התוכנה). מה שאומת:
  תוכן המניפסט בקובץ שנבנה, הידור סקריפט ה-NSIS, מיקום ההרמה בסדר הפעולות של
  `.onInit`, וההגנות בבדיקות האוטומטיות. התרחישים בטבלה למעלה הם האימות בפועל.
